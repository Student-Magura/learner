# Learner — командні каталоги й синхронізація бібліотеки

**Дата:** 2026-10-13
**Статус:** дизайн затверджено, готовий до планування реалізації
**Базується на:** `2026-09-20-drive-course-player-design.md` і коміті `d4e0c3d` (вбудований каталог)

## Проблема

Зараз каталог курсів лише один — він задається під час збірки (`VITE_CATALOG_FOLDER_ID`) і однаковий
для всіх. Менші команди підтримують власні каталоги, які не поширені на загал, і хочуть, щоб нові
курси з такої папки так само з'являлися в бібліотеці самі.

Водночас поле для посилання на курс займає на головному екрані постійне місце, хоча користуються ним
рідко.

Окремо відома прогалина: власні курси не синхронізуються між пристроями — на новому пристрої їх
треба додавати знову. Для каталогів це було б ще прикріше, тому вирішуємо обидва питання разом.

## Обсяг

**Входить:**
- кнопки «+ Курс» і «+ Каталог» на головному екрані, кожна відкриває діалог; постійне поле URL зникає;
- додавання каталогу за посиланням на папку Drive, з передпереглядом знайдених курсів;
- прибирання доданого каталогу;
- автоматична поява нових курсів у будь-якому каталозі — на старті й при поверненні вкладки у фокус;
- синхронізація між пристроями списку доданих каталогів **і** власних курсів;
- бібліотека як набір секцій: вбудований каталог, кожен доданий каталог, «Власні курси».

**Не входить:**
- автоматичний rescan уроків у вже відомих курсах (лишається кнопка на сторінці курсу);
- вкладені каталоги (каталог усередині каталогу);
- ручне сортування секцій;
- поширення каталогу посиланням із самого застосунку — доступом керують права Drive;
- автовиявлення «це курс чи каталог». За структурою їх не розрізнити: курс, розбитий на секції,
  теж містить лише підпапки з відео. Будь-яка евристика хибно спрацьовувала б на звичайних курсах.

## Ключове рішення: де живе список підписок

Розглянуто три варіанти.

**1. Окремий файл `learner-library.json` в `appDataFolder` — обрано.** Поруч із
`learner-progress.json`, зі злиттям per-entry last-write-wins і tombstone для видалень.
Файл прогресу — єдині невідтворювані дані — не змінює формату.

**2. Бібліотека всередині `learner-progress.json` — відкинуто.** Одна синхронізація замість двох,
але змінює формат найціннішого файлу. Стара версія PWA на іншому пристрої (оновлюється не одразу)
відкинула б або затерла б новий розділ.

**3. Виводити список із Drive (зірочки, ярлики в спецпапці) — відкинуто.** Потребує scope на запис,
а scope зараз `drive.readonly`, і змушує керувати бібліотекою з інтерфейсу Drive.

## Модель даних

Зараз `Course` змішує два різні за природою факти: що користувач **обрав** (невідтворюване,
синхронізується) і що **зараз лежить у Drive** (кеш). Розділяємо їх.

```ts
/** Синхронізується через learner-library.json. Ключ — Drive folderId. */
type Subscription = {
  kind: 'catalog' | 'course';
  addedAt: number;
  /** epoch ms. Основа для per-entry last-write-wins. */
  updatedAt: number;
  /** Tombstone: «прибрати» мусить дійти до інших пристроїв. */
  removed: boolean;
};
type Library = Record<string, Subscription>;

/** Локальний кеш складу каталогу. Завжди перебудовується з Drive. */
type CatalogSnapshot = {
  id: string;          // Drive folderId каталогу
  title: string;       // назва папки Drive
  courseIds: string[]; // folderId підпапок на момент останнього listFolder
  lastSyncedAt: number;
};

/** Кеш відсканованого курсу. Поле `source` зникає. */
type Course = { id: string; title: string; addedAt: number; tree: FolderNode; lastScannedAt: number };
```

**Секції на екрані виводяться, а не зберігаються:**
- вбудований каталог — неявна, неприбиранна підписка, якої немає в `Library`; якщо його id
  випадково опиниться в `Library`, показується один раз, як вбудований;
- кожна активна (`removed: false`) підписка `catalog` → секція з курсами з `CatalogSnapshot.courseIds`;
- активні підписки `course` → секція «Власні курси».

Наслідки:
- курс у двох каталогах показується в обох секціях; прогрес один, бо ключований `fileId`;
- власний курс, що пізніше з'явився в каталозі, показується в обох секціях; власна підписка лишається,
  і курс не зникне, якщо каталог прибрати;
- `Course` — чистий кеш: курс, на який ніщо не посилається, стирається з IndexedDB без втрат.
  **Прогрес не стирається ніколи** — незмінне правило проєкту.

**Злиття `Library`** — чиста функція `mergeLibrary(local, remote)`, побудована за зразком
`mergeProgress`: per-key last-write-wins за `updatedAt`, при рівності перемагає локальний.
Повторне додавання після видалення має новіший `updatedAt` і знімає tombstone. Tombstone не
прибираються — записів десятки, а не тисячі.

**Розбір віддаленого файлу** — `parseLibrary`: записи перевіряються поштучно (тип `kind`, скінченні
`addedAt`/`updatedAt`, булевий `removed`), биті відкидаються, як у `parseProgress`.

### IndexedDB v2 і міграція

`DB_VERSION` 1 → 2, нові стори `library` (keyPath `id`) і `catalogs` (keyPath `id`).
Міграція в `upgrade`, у тій самій транзакції:
- курс без `source` або з `source: 'own'` → `Subscription { kind: 'course', addedAt: course.addedAt,
  updatedAt: course.addedAt, removed: false }`;
- курси з `source: 'catalog'` → один `CatalogSnapshot` вбудованого каталогу з їхніми id
  (`title` — порожній, заповниться першим reconcile; `lastSyncedAt: 0`);
- поле `source` видаляється з записів курсів.

Дерева не скануються заново. `openLearnerDb` отримує id вбудованого каталогу параметром
(`services.ts` його вже знає). Якщо в збірці каталогу немає, а курси з `source: 'catalog'` є,
знімок не створюється — такі курси стають кешем без посилань і зникають при першому reconcile
(прогрес лишається).

`docSync` переносить без змін уже вистраждану логіку `syncEngine`: транзакційне злиття проти
поточного вмісту сховища, `pushed`-знімок для рішення про push, `modifiedTime` для пропуску
зайвого завантаження, злипання паралельних проходів. Ключі в `meta` задаються параметром: прогрес лишає наявні
`remoteModifiedTime` і `pushedProgress` (щоб оновлення не спричинило зайвий повний push),
бібліотека бере `libraryRemoteModifiedTime` і `pushedLibrary`.

## Потоки даних

### Старт

1. З IndexedDB піднімаються `library`, `catalogs`, `courses`, прогрес — екран малюється з кешу.
2. `syncFromRemote` у фоні синхронізує обидва документи — прогрес і бібліотеку.
3. Після злиття бібліотеки — **reconcile**:
   - для кожного активного каталогу (і вбудованого) — один `listFolder` → оновлений `CatalogSnapshot`;
   - курси, на які посилаються підписки або знімки, але яких немає в кеші, скануються паралельно,
     **не більше 4 одночасно**;
   - курси, на які ніщо не посилається, стираються з кешу (прогрес лишається).

`ready` не чекає на reconcile, як і зараз не чекає на `syncCatalog`.

### Коли каталоги перевіряються на нові курси

На старті й при поверненні вкладки у фокус — не частіше ніж раз на 10 хвилин (тротлінг за часом
останнього reconcile). Один прохід за раз: паралельні виклики злипаються, як зараз `catalogRun`.
Уже відомі курси не пересканьовуються.

### Додати каталог

1. **Крок 1** — `previewCatalog(input)`: `parseFolderId` → `getFile` (назва) + `listFolder` →
   `{ id, title, courses: { id, title }[] }`. У сховище нічого не пишеться.
   Відмова, якщо id уже є серед активних каталогів або це вбудований каталог.
2. **Крок 2** — `addCatalog(preview)`: підписка `catalog` у `library`, знімок — з передперегляду;
   push бібліотеки **одразу**, без дебаунсу (зміна рідкісна й важлива). Далі reconcile сканує курси
   у фоні; секція з'являється одразу з картками «Скануємо…».

### Додати курс

Як зараз (`parseFolderId` → `scanCourse` → кеш), плюс підписка `course` і негайний push.
Відмова, якщо курс уже є в одному з каталогів — з назвою каталогу в повідомленні.

### Прибрати каталог або курс

Tombstone (`removed: true`, новий `updatedAt`) → негайний push → reconcile стирає курси, на які більше
ніщо не посилається. На інших пристроях — при наступній синхронізації.

## Стан для UI

У сторі, поруч із наявними полями:
- `library: Library`, `catalogs: Record<string, CatalogSnapshot>`;
- `catalogStatus: Record<catalogId, 'syncing' | 'no-access'>` — відсутність ключа = все гаразд;
- `courseStatus: Record<courseId, 'scanning' | 'error'>`.

`catalogSyncing: boolean` зникає — його замінює `catalogStatus`.

## Візуальний дизайн

Макети погоджено у візуальному компаньйоні: варіант A — **окрема секція на кожен каталог**.

**Заголовок.** «Мої курси» + праворуч «+ Каталог» (обведена) і «+ Курс» (залита — основна дія,
бо курс додають частіше). На телефоні обидві — одним рядом під заголовком, порівну ширини.

**Порядок секцій:** вбудований каталог → додані каталоги за `addedAt` → «Власні курси».
Курси всередині каталогу — natural sort за назвою, як зараз. Власні курси — за `addedAt` підписки.

**Секція каталогу.** Заголовок — назва папки Drive. Вбудований підписаний «для всіх» і не має меню.
Доданий має меню «⋯»: «Відкрити в Drive ↗» і «Прибрати каталог» (з підтвердженням, як нині
`window.confirm` у курсу).

**Стани:**

| Стан | Вигляд |
|---|---|
| reconcile каталогу триває | біля заголовка «Оновлюємо… 2 з 6» |
| курс відомий зі знімка, але ще не сканований | сіра неклікабельна картка «Скануємо…» |
| скан одного курсу впав | картка «Немає доступу до папки»; повтор при наступному reconcile |
| `listFolder` каталогу дав 403/404 | біля заголовка «⚠ Немає доступу до каталогу — показуємо збережене»; курси зі знімка лишаються |
| офлайн | нічого не показуємо — офлайн для застосунку норма |
| бібліотека порожня (і вбудованого каталогу немає) | одна рамка-підказка замість секцій |

Секція «Власні курси» показується лише тоді, коли в ній є хоча б один курс.

**Діалог «Додати курс».** Заголовок, пояснення «Папка Google Drive, у якій лежать відео курсу, можна
з підпапками-розділами», поле посилання, «Скасувати» / «Додати курс» (під час скану — «Сканую…»).
Помилка — під полем, як зараз. Успіх закриває діалог.

**Діалог «Додати каталог курсів».**
- Крок 1: пояснення «Папка Drive, у якій кожна підпапка — окремий курс. Нові курси, які туди
  викладуть, з'являтимуться самі», поле, «Скасувати» / «Далі».
- Крок 2: назва каталогу, кількість курсів, перші кілька назв і «…ще N»; «Назад» / «Додати каталог».
  Якщо підпапок немає — «У папці немає курсів-підпапок», кнопка неактивна.
  Саме цей крок захищає від плутанини: побачивши «01 Вступ, 02 Основи…», людина зрозуміє, що
  вставила курс.

Обидва діалоги — нативний `<dialog>` зі `showModal()`: фокус-пастка, Esc і фон браузер дає сам.

## Обробка помилок і граничні випадки

| Ситуація | Поведінка |
|---|---|
| каталог уже додано або це вбудований | крок 1: «Цей каталог уже є в бібліотеці» |
| у папці каталогу немає підпапок | передперегляд: «У папці немає курсів-підпапок», додати не можна |
| посилання не на папку / немає доступу | наявні повідомлення `parseFolderId` і `rethrowFriendly` |
| курс уже є в каталозі | «Цей курс уже є в каталозі „…“» |
| каталог прибрали на одному пристрої й одночасно додали на іншому | перемагає пізніша дія (LWW) |
| `learner-library.json` зіпсований | биті записи відкидаються поштучно |
| пристрій зі старою версією застосунку | файл прогресу не змінився — старий клієнт працює й не бачить бібліотеку |
| збій синхронізації бібліотеки | локальна бібліотека працює; спроба при наступній нагоді |

## Тестування

**Юніт (Vitest), чиста логіка:**
- `mergeLibrary`: tombstone проти повторного додавання в обидва боки, однакові `updatedAt`,
  записи лише з одного боку;
- `parseLibrary`: невідомий `kind`, NaN, відсутні поля, не-об'єкт;
- `reconcile`: новий каталог, курс зник із каталогу, курс у двох каталогах, курс без посилань → GC,
  власна підписка + той самий курс у каталозі, прибраний каталог;
- `sections`: порядок, вбудований id у `Library`, порожня бібліотека, «Власні курси» без курсів;
- `docSync`: наявні тести `syncEngine` проходять без змін — доказ, що поведінка прогресу та сама.

**Міграція IndexedDB v1 → v2** на `fake-indexeddb`: курси без `source`, з `'own'`, з `'catalog'`;
дерева на місці, підписки й знімок створено, `source` зник.

**Стор із MSW:** додати/прибрати каталог; два екземпляри стору на одному `appDataFolder` — каталог,
доданий в одному, з'являється в другому, прибирання поширюється.

**UI (RTL):** обидва діалоги, передперегляд і його порожній стан, стани секцій, меню «⋯».

**Вручну:** два браузерні профілі на одному акаунті — додавання й прибирання каталогу й власного
курсу поширюються.

## Критерії готовності

1. На головному екрані немає постійного поля URL; «+ Курс» і «+ Каталог» відкривають діалоги.
2. Каталог додається за посиланням через передперегляд і показується окремою секцією з назвою папки.
3. Новий курс, викладений у доданий каталог, з'являється після перезапуску або повернення у вкладку
   (з урахуванням 10-хвилинного тротлінгу).
4. Каталог і власний курс, додані в одному браузерному профілі, з'являються в іншому профілі того
   самого акаунта; прибирання теж поширюється.
5. Після оновлення наявні власні курси й курси вбудованого каталогу на місці без пересканування,
   прогрес цілий.
6. Прогрес не видаляється в жодному сценарії прибирання.
7. `npm test` і `npm run build` зелені.
